### ทำอะไรจากหน้าจอได้แล้วบ้าง

ผู้ดูแลไม่ต้องเขียน SQL อีกต่อไปสำหรับ: **ผู้ใช้และกลุ่ม · โปรเจกต์ · สิทธิ์ (ตารางติ๊ก) ·
workflow (สถานะ + ปุ่ม) · ประเภทงาน + การผูกเข้าโปรเจกต์ · ฟิลด์เพิ่มเติม + ตั้งว่าโปรเจกต์ไหนถามอะไร ·
ผลการแก้ไข · ปฏิทินวันหยุด + การยืนยันรายปี**

ยังต้องใช้ SQL หรือสคริปต์: **กฎสามชั้นของ transition** (ใครเห็นปุ่ม · ต้องกรอกอะไร · ทำอะไรต่อ) ·

### สิ่งที่ต้องรู้ก่อนขึ้น pilot

1. 🔴 **ยังไม่มีใครกรอกวันหยุดจริงลงปฏิทิน** — ปี 2569 มี 16 วันที่ชื่อว่า "วันหยุดราชการ"
   เหมือนกันหมดและ **ไม่มีวันสำคัญทางพุทธศาสนาสักวัน** · ปี 2570 **ว่างเปล่าทั้งปี**
   ตั้งแต่ 1 ม.ค. 2570 สงกรานต์จะถูกนับเป็นวันทำการ
   หน้าจอกรอกและยืนยันพร้อมแล้วที่ `/admin/calendars` — **เหลือแค่คนอ่านประกาศจริงแล้วกรอก**
   ตัวเลข SLA ทุกตัวติดป้าย "เชื่อไม่ได้" อยู่จนกว่าจะมีคนยืนยัน
2. 🟡 **ยังไม่มีใครกรอกรายการบริการจริง** — หน้าจอพร้อมแล้วที่ `/admin/catalog` แต่ `catalog_item` ยังมี 0 แถว · จนกว่าจะมีคนกรอก ผู้แจ้งก็ยังพิมพ์อิสระเหมือนเดิม
3. 🟡 **ยังไม่มี LINE** — องค์กรใช้ LINE อยู่ทุกวัน แต่ระบบแจ้งเตือนได้แค่ในแอปกับอีเมล
4. 🟡 **ยังเปลี่ยนสถานะทีละหลายใบไม่ได้** — HQL · Saved Filter · Bulk Edit (มอบหมาย/ความสำคัญ) ·
   การแบ่งหน้า ใช้จากหน้าจอได้แล้ว · เส้นทางคิวรีดูได้ลึกสุด 10,000 รายการ
   ตามเพดาน `max_result_window` ของ OpenSearch

## กติกาการเปลี่ยนขอบเขต

1. คำขอใหม่ทุกข้อเข้า backlog พร้อมการประมาณการ — **ไม่มีการ "เพิ่มนิดเดียว"**
2. การเพิ่มสิ่งใดเข้า v1.0 ต้อง **แลกออก** สิ่งที่มีขนาดใกล้เคียงกันเสมอ
   ผู้อนุมัติการแลกคือ PO และต้องบันทึกไว้ท้ายเอกสารนี้
3. ทบทวนขอบเขตอย่างเป็นทางการ **ทุกสิ้นเฟสเท่านั้น** ไม่ใช่ทุกสัปดาห์
4. ถ้าสิ้นเฟสไหนไม่ผ่าน Exit Criteria ต้องตัดสินใจอย่างเป็นทางการว่า
   **ยืดเวลา หรือ ตัดขอบเขต** — ห้ามเริ่มเฟสถัดไปโดยปล่อยเฟสเดิมค้าง
